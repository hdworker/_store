# _store — эталонное хранилище

Единая точка хранения: настройки, эталонная XML-конфигурация, вендорские
расширения, опубликованные сборки. Read-only для агентов; запись — только через
шаг «publish» по правилам ниже.

**Процесс разработки целиком (хранилище, сборка, запуск, проверка, MCP/async/cc-status) —
[`PROCESS.md`](PROCESS.md).**

## Структура

```
_store\
  .v8-project.json   # единый реестр: v8path, базы test1..test7, default (стандартный формат скиллов)
  store-index.json   # инвентаризация: проекты, расширения, артефакты (генерируется, руками не правится)
  vendor\
    config\          # CF/CFE сборки конфигурации — для переноса и развёртывания с нуля
    extensions\      # вендорские расширения (*.cfe), все используемые
  reference\         # XML рабочей базы (immutable)
    config\          # XML типовой конфигурации по версиям
    extensions\<Имя>\<Версия>\  # XML всех расширений (снимки)
  extensions\        # опубликованные сборки: CFE/EPF/ERF
    <Имя>\<X.Y.Z>\<Имя>_v<X.Y.Z>.cfe
  baselines\         # «золотые» выгрузки тестовых баз по датам
```

## Правила публикации (без рассинхрона)

1. Имя артефакта неизменно: `<Имя>_v<X.Y.Z>.cfe|epf|erf`; версия = `<Version>`
   из `Configuration.xml`.
2. Публикация **только добавлением** (create-only): файл с таким именем уже
   есть — отказ; хэш отличается — конфликт версий, поднять версию. Перезаписи нет.
3. **Бронь версии**: `_store\extensions\<Имя>\current.json` создаётся атомарно
   (`O_EXCL`): {версия, агент/вкладка, база, время}. Пока бронь жива — другой
   агент видит «занято»; протухшие брони (> N часов) освобождаются.
4. Агенты правят в **своих копиях проектов** (`src`), store — публикация/чтение.
   Финальная загрузка и проверка — `1c-check-task` в согласованной тестовой базе.
5. `reference\` не изменяется и не удаляется; новая версия — новая папка.
6. `store-index.json` — источник «что где лежит и какой версии»; перегенерируется.

## Синхронизация (кто за что отвечает)

- Базы и v8path — только в `_store\.v8-project.json` (единый источник).
- Детали проекта (его расширения, сборки) — только в `.v8-project.json` самого проекта.
- `store-index.json` — **генерируемый** кэш инвентаризации; руками не правится,
  поэтому не может «разъехаться»: у каждого факта один владелец.

## Артефакты в проектах

Рабочие CFE/EPF/ERF остаются в `<проект>\build` (агент работает в своей копии
проекта). В `_store\extensions` попадают только опубликованные версии.
